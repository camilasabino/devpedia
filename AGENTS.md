# AGENTS.md

This file provides guidance to coding agents such as Codex when working with code in this repository. It mirrors `CLAUDE.md`; keep both in sync.

## Project

DevPedia (*A handbook for Software Engineering*): a bilingual static Astro site of guides organized by topic, subtopic and section.

There is no `/blog`, no redirects and no blog terminology: the unit is the **Guide** (`Guía`), grouped under **Topic** (`Tema`) and **Subtopic** (`Subtema`).

## Commands

```bash
npm install
npm run dev              # http://localhost:4322
npm run build            # astro build → dist/, then pagefind --site dist
npm run preview
npm run check            # astro check
npm test                 # Vitest (test/)
npm run check:links      # after npm run build
npm run check:en-language  # after npm run build
```

There is no lint or formatting script. Search only works on a build (`preview`), since Pagefind indexes `dist/` after `astro build`.

## Content model

`src/content.config.ts`, `src/lib/content-model.ts`: Topic → optional Subtopic → Guide, with optional `sections` to group guides inside a topic or subtopic. Files: `src/content/{topics,subtopics}/{es,en}/*.yaml` and `src/content/guides/{es,en}/<topic>/[<subtopic>/]<id>.mdx`. `id`, `slug` and `order` are separate on purpose:

- `id`: stable conceptual identity, English kebab-case, the same in both languages. It pairs ES/EN, drives hreflang and analytics, and never changes. Do not derive it from the slug or the path.
- `slug`: localized URL segment only. Keep published slugs stable.
- `order`: pedagogical position among siblings, never identity.

`src/lib/content.ts` runs `validateContentModel` at build time and fails on any broken rule (pairing, references, unique ids/slugs/orders, section usage, Claude Code under AI Engineering…); `test/content-model.test.ts` runs the same rules on the real files.

## Routing

Spanish at `/`, English under `/en/`, generated by `src/pages/[...path].astro` and `src/pages/en/[...path].astro` from `ContentIndex.routes(lang)`: `/<topic>/`, `/<topic>/<guide>/`, `/<topic>/<subtopic>/`, `/<topic>/<subtopic>/<guide>/`. Alternates, breadcrumbs, previous/next and the sitemap are resolved by id through `ContentIndex`. `prerenderConflictBehavior: 'error'` fails the build on URL clashes.

## Code

**Pure logic in `src/lib/`** (tested in `test/`): `guide.ts` (sequence, reading time, TOC), `hub.ts` (section grouping), `seo.ts` (JSON-LD, absolute URLs), `search.ts` (result context), `analytics.ts` (event contract: `guide_view`, `topic_view`, `search`, `search_result_click`, `next_guide_click`, `share`, `language_change`; conceptual ids only, never the search query). Do not add events casually.

**MDX components** live in `src/components/mdx/`. They cannot receive a `lang` prop, so they read the language through `langFromPath` in `src/i18n/index.ts`. Mermaid renders client-side and lazily (build-time rendering needs Playwright browsers, which the Cloudflare build image lacks). Hand-authored UML figures (`mdx/uml/`) cover what Mermaid cannot draw. `<use>`/`<marker>` shadow trees cannot be reached by class selectors; rely on `currentColor`.

**Markdown pipeline** (`astro.config.mjs`): Shiki dual theme from `src/lib/shiki-theme.ts`; rehype plugins passed through `markdown.processor: unified({...})`. `rehype-guide-enhancements.ts` wraps tables in a focusable scroll container and makes `<pre>` focusable; heading anchors are added client-side because Astro's slugger runs after user rehype plugins.

**Styles:** Tailwind v4 configured in CSS (`src/styles/global.css`, tokens in `theme.css` and `surfaces.css`), no `tailwind.config`, no frontend framework. `docs/` is excluded from Tailwind's class scan.

## Configuration and deployment

`SITE_URL` (default `https://devpedia.camilasabino.dev`) and optional `GA_MEASUREMENT_ID` come from the environment or `.env`. Every absolute URL derives from `SITE_URL`, so never hard-code the domain. Empty `GA_MEASUREMENT_ID` means no script and no request.

Static assets on Cloudflare Workers Builds: `wrangler.jsonc` (`name: devpedia`, `./dist`, custom domain `devpedia.camilasabino.dev`), deployed with `npx wrangler deploy` (Wrangler is a devDependency). No adapter, no Worker script, no bindings. Do not deploy unless asked.

## Editorial

Antes de crear, editar o revisar guías o temas en español (`src/content/**/es/`), leé `docs/EDITORIAL_GUIDELINES.md`. Para la edición en inglés (`src/content/**/en/`), la guía es `docs/EN_EDITORIAL_GUIDE.md`. `docs/I18N_PROGRESS.md` registra cómo se emparejan las dos ediciones y las decisiones abiertas. No dupliques esos criterios acá.
